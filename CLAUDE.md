# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project status

Rust library crate (`ansi-nist-itl`, edition 2024, MIT) for reading and writing ANSI/NIST-ITL biometric transaction files (`.nist`, `.eft`, `.an2`, `.int`). The repo is currently a bare scaffold (`src/lib.rs` contains only a doc comment, no dependencies). **`docs/PRD.md` (in French) is the source of truth for scope, requirement IDs (`LIB-xx`, `QA-xx`, `DATA-xx`) and milestones** — read it before designing any module, and reference requirement IDs in commits/PRs where relevant.

## Commands

```sh
cargo build
cargo test                         # all tests (unit, integration, doctests)
cargo test <name_substring>        # single test or group
cargo test --doc                   # doctests only
cargo clippy --all-targets -- -D warnings
cargo fmt --check
cargo doc --no-deps
```

CI is expected to run test, clippy `-D warnings`, rustfmt and `cargo doc` on Linux/macOS/Windows (QA-06); fuzzing uses `cargo-fuzz` (QA-04).

## Domain model (from the PRD)

- A message is split into records using the CNT field (1.003). Hierarchy: `Message` → `Record` → `Field` → `Subfield` → `Item`, with separators FS `0x1C`, GS `0x1D`, RS `0x1E`, US `0x1F`.
- Two record encodings must coexist:
  - **Tagged** records `T.NNN:` — Types 1, 2, 9, 10, 13–21, 98, 99.
  - **Binary fixed-header** records — Types 3 to 8 (typed headers per record type, pack/unpack).
- Binary payloads (field 999 image data, Type-3..8 data) are exposed as raw bytes without copying. **Image decoding (WSQ, JPEG 2000) is out of scope.**
- Type-1 is unique and cannot be deleted; LEN, CNT and IDC are recomputed on write.
- Error kinds mirror `nistitl` (BAD_RECORD, BAD_TAG_NAME, NIST_TOO_SHORT, …, see LIB-11) as a single `enum Error` carrying position (record, field, byte offset).

## Non-negotiable design constraints

- **Byte-exact round-trip** (LIB-12): reading then writing an unmodified file must produce identical bytes — preserve field order and original formatting; do not normalise/re-sort like `nistitl` does.
- **Never panic on input**: no `unwrap`/indexing that can panic on data derived from input; parser is fuzzed.
- **Strict and tolerant modes** (LIB-13/14): tolerant mode opens truncated/malformed files partially and returns located diagnostics.
- Core works on `&[u8]`; file/`Read` helpers are conveniences only. No UI or I/O assumptions.
- `#![forbid(unsafe_code)]` unless justified and documented.
- Minimal dependencies; optional features behind Cargo features (`serde`, `xml`, `validation`).
- Prefer enums/types over conventions (record types, compressions, positions). Every public item documented with a runnable example. Public docs/API in English.

## Test data and licensing

- **Never commit real NIST files** — they contain biometric/personal data. Only synthetic files (generated by the crate or from public NIST/standard examples) may be added (DATA-01/02). The real-corpus oracle tests run outside this repo via a configurable path (DATA-03).
- `nistitl` (IDEMIA, Python, CeCILL-C) is used only as a **behaviour oracle**: compare outputs, but never translate or copy its code into this crate.
